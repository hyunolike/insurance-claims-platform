# 00. 도메인 사전 — 실손의료보험 청구

> 이 문서가 **유비쿼터스 언어의 원천**이다. 코드의 클래스명·필드명·이벤트명·DB 컬럼명은 모두 여기 정의된 용어를 따른다.
> 여기 없는 용어를 코드에 새로 만들면, 코드가 아니라 이 문서를 먼저 고친다.

---

## 0. 이 문서를 읽는 법

실손의료보험 청구 심사는 **"얼마를 줄 것인가"를 정하는 계산 문제**가 아니라,
**"어떤 근거로 이 금액이 나왔는가를 설명할 수 있는가"** 의 문제다.

민원·분쟁·금융감독원 검사에서 요구받는 것은 지급액이 아니라 **산출 근거**다.
따라서 이 시스템의 모든 설계 결정은 다음 한 문장으로 수렴한다:

> **심사 결과의 모든 단계는 재현 가능하고, 설명 가능하며, 사후에 변조 불가능해야 한다.**

## 1. 계약 축 (business-support가 원천)

| 용어 | 영문/코드 | 정의 |
|---|---|---|
| 계약 | `Policy` | 보험계약. 계약번호(`policyNo`)로 식별 |
| 계약자 | `PolicyHolder` | 보험료 납입 의무자, 계약 변경 권한자 |
| 피보험자 | `Insured` | 보험사고의 대상이 되는 사람. **청구의 주체는 피보험자 기준** |
| 수익자 | `Beneficiary` | 보험금 수령인. 실손은 통상 피보험자 본인 |
| 담보 | `Coverage` | 계약 안의 개별 보장 단위(급여 입원의료비, 비급여 통원의료비, 3대 비급여 특약 등) |
| 주계약 | `BaseCoverage` | 4세대 기준 급여 의료비 |
| 특약 | `Rider` | 비급여 의료비, 3대 비급여(도수·주사·MRI) 등 |
| 보험기간 | `PolicyPeriod` | 책임개시일 ~ 만기일. **사고일이 이 구간 안이어야 보상** |
| 책임개시일 | `effectiveDate` | 초회보험료 납입 + 승낙 시점. 이 날 이전 사고는 부보 대상 아님 |
| 부담보 | `Exclusion` | 언더라이팅 결과 특정 부위·질병을 일정 기간 보장 제외. `EEC`라고도 함 |
| 면책기간 | `WaitingPeriod` | 계약일로부터 일정 기간 보장하지 않는 기간 (특약별 상이) |
| 계약상태 | `PolicyStatus` | 정상 / 납입최고 / 실효 / 부활 / 해지 / 만기 |
| 실효 | `LAPSED` | 보험료 미납으로 효력 상실. **실효 중 사고는 부지급** |
| 부활 | `Reinstatement` | 실효 계약의 효력 회복. 재고지 + 면책기간 재기산 |
| 세대 | `generation` | 실손 상품 세대. 자기부담률·보장구조의 1급 분기 기준 |

### 1.1 실손의료보험 세대

세대별로 자기부담 구조가 근본적으로 다르다. **심사 룰의 최상위 분기**다.

| 세대 | 통상 판매기간 | 구조 | 자기부담 성격 |
|---|---|---|---|
| 1세대 | ~2009.09 | 표준화 이전, 상품별 상이 | 자기부담 거의 없음(100% 보상형 다수) |
| 2세대 | 2009.10~2017.03 | 표준화 실손 | 급여/비급여 통합, 낮은 정률 |
| 3세대 (착한실손) | 2017.04~2021.06 | 3대 비급여를 특약 분리 | 급여·비급여 정률 차등 |
| 4세대 | 2021.07~ | 급여=주계약 / 비급여=특약 완전 분리 | 정률 + 최소공제금액, 비급여 이용량 연동 보험료 할인·할증 |
| 5세대 이후 | 후속 개정 | 중증/비중증 차등 등 | — |

> ⚠️ **설계 원칙**: 세대별 수치(자기부담률, 최소공제금액, 한도)를 **코드에 하드코딩하지 않는다.**
> 상품 마스터(`product_generation_policy`)에 데이터로 두고, 룰 엔진은 파라미터를 주입받는다.
> 이유: (1) 제도 개정이 잦다 (2) 같은 세대 안에서도 상품별 예외가 있다 (3) 과거 사고건은 과거 기준으로 재현되어야 한다.
> 이 문서에 등장하는 모든 수치는 **설계 예시**이며, 구현 시 실제 약관·상품 마스터로 검증해야 한다.

## 2. 의료·청구 축 (claims-platform이 원천)

| 용어 | 영문/코드 | 정의 |
|---|---|---|
| 청구 | `Claim` | 피보험자가 제출한 보험금 지급 요청 1건 |
| 청구번호 | `ClaimNo` | 대외 식별자. `CLM-YYYYMMDD-NNNNNN` |
| 사고 | `Accident` | 보험금 지급 사유가 되는 사건. 상해 또는 질병 |
| 사고일 | `accidentDate` | 상해는 사고 발생일, 질병은 **최초 진단일**. 계약 유효성 판정 기준일 |
| 진료 | `Treatment` | 실제 의료행위. 청구 1건에 여러 진료건이 붙을 수 있음 |
| 진료일 | `treatmentDate` | 실제 진료가 이루어진 날. 한도 차감의 귀속 연도 기준 |
| 진료구분 | `TreatmentType` | 입원 / 통원(외래) / 처방조제 |
| 요양기관 | `MedicalInstitution` | 병·의원·약국. 요양기관번호로 식별 |
| 요양기관 종별 | `InstitutionGrade` | 의원 / 병원 / 종합병원 / 상급종합병원 / 약국. **최소공제금액이 종별로 다름** |
| 질병분류코드 | `KcdCode` | 한국표준질병사인분류(KCD). 면책 판정의 핵심 입력 |
| 급여 | `COVERED` | 국민건강보험 적용 항목. 이 중 **본인부담금**이 보상 대상 |
| 비급여 | `UNCOVERED` | 건강보험 미적용 항목. 전액이 보상 대상(자기부담 차감 후) |
| 본인부담금 | `patientShare` | 급여 항목 중 환자가 낸 금액. **공단부담금은 보상 대상 아님** |
| 공단부담금 | `nhisShare` | 국민건강보험공단이 부담한 금액. 보상 대상 제외 |
| 3대 비급여 | `MajorUncovered` | 도수치료·체외충격파·증식치료 / 비급여 주사료 / 비급여 MRI·MRA. 별도 특약·별도 한도 |
| 자기부담금 | `Deductible` | 보상액에서 차감하는 금액. **정률과 최소공제금액 중 큰 값** |
| 정률 자기부담 | `coinsuranceRate` | 대상금액 × 비율 |
| 최소공제금액 | `minDeductible` | 통원 시 요양기관 종별로 정해진 정액 하한 |
| 보상액 | `payableAmount` | 자기부담금 차감 후, 한도 적용 후의 지급 대상 금액 |
| 보장한도 | `BenefitLimit` | 연간 한도 / 회당 한도 / 연간 횟수 한도 |
| 보장 사용 원장 | `BenefitLedger` | 계약·담보·보장연도별 누적 사용액과 사용 횟수. **한도 판정의 단일 진실 공급원** |
| 보장연도 | `benefitYear` | 한도가 리셋되는 주기. 통상 계약 응당일 기준 1년 |
| 비례보상 | `ProRataSharing` | 동일 피보험자가 실손 2건 이상 가입 시, 실제 손해액 한도로 각 계약이 분담 |
| 본인부담상한제 | `OutOfPocketCap` | 건강보험 본인부담 상한 초과분 사후 환급. **환급 시 기지급 보험금 환수 대상** |

### 2.1 자기부담금 계산 구조 (실손의 핵심)

```
자기부담금 = max( 대상금액 × 정률, 최소공제금액 )
보상액    = 대상금액 - 자기부담금
```

**입원은 최소공제금액이 없고 정률만 적용**, **통원·처방조제는 최소공제금액이 적용**된다.
급여와 비급여는 **각각 따로** 계산한 뒤 합산한다. 이 순서를 섞으면 금액이 틀어진다.

## 3. 심사 축

| 용어 | 영문/코드 | 정의 |
|---|---|---|
| 심사 | `Adjudication` | 청구 1건에 대한 지급 여부·금액 판정 행위 |
| 자동심사 | `AutoAdjudication` | 룰 엔진이 사람 개입 없이 종결한 심사 |
| 수동심사 | `ManualReview` | 심사자(보상 담당자)가 판단하는 심사. business-support 백오피스가 아닌 **claims의 심사자 콘솔** 영역 |
| 회부 | `Refer` | 자동심사가 판단을 보류하고 사람에게 넘기는 것. **거절이 아니다** |
| 판정 | `Decision` | `APPROVED` / `PARTIALLY_APPROVED` / `DENIED` / `REFERRED` |
| 부지급 | `Denial` | 지급하지 않기로 한 판정. 반드시 **부지급 사유코드**를 동반 |
| 일부지급 | `PartialApproval` | 청구액 일부만 지급. 차액의 사유를 항목별로 설명해야 함 |
| 심사 트레이스 | `AdjudicationTrace` | 어떤 룰이, 어떤 입력으로, 어떤 결과를 냈는지의 전체 기록. **변조 불가·영구 보존** |
| 계약 스냅샷 | `PolicySnapshot` | 사고일 시점의 계약·담보·부담보 상태를 청구 건에 **복제 저장**한 것 |
| 지급기한 | `PaymentDueDate` | 표준약관상 보험금 지급 기한. 영업일 기준 |
| 지연이자 | `LateInterest` | 지급기한 초과 시 가산하는 이자 |
| 이상징후 탐지 | `FDS` | Fraud Detection System. 단기 다발 청구·특정 기관 집중 등 |
| 환수 | `Reclaim` | 이미 지급한 보험금을 회수. 본인부담상한제 환급, 착오지급, 사기 적발 시 |
| 재심사 | `Reopen` | 부지급·일부지급에 대한 이의제기로 다시 심사하는 것 |

### 3.1 표준약관상 지급기한 (설계 예시 — 실제 약관 확인 필요)

| 구분 | 기한 | 비고 |
|---|---|---|
| 원칙 | 청구서류 접수일로부터 **3영업일 이내** | 조사 불필요한 건 |
| 조사·확인 필요 | 접수일로부터 **10영업일 이내** | 사유 발생 시 |
| 10영업일 초과 | 구체적 사유·예정일 **통지 의무** | 통지 누락은 그 자체로 민원 사유 |
| 초과 지급 | **지연이자 가산** | 보험계약대출이율 등 기준 |

> 이 기한은 **시스템이 능동적으로 추적해야 하는 SLA**다. 화면에 표시만 하는 값이 아니라,
> 임박 시 알림을 띄우고 초과 시 지연이자를 자동 산출하는 **1급 도메인 개념**으로 다룬다.

### 3.2 소멸시효

보험금청구권의 소멸시효는 **3년**(상법 제662조). 사고일로부터 3년이 지난 청구는 접수 단계에서 차단한다.
단, 시효 완성은 법적 판단 여지가 있어 **자동 부지급이 아니라 수동심사 회부**로 설계한다.

## 6. 금액 표기 규칙

- 통화는 **KRW 단일**. 다통화 지원은 범위 밖 — `Money`에 통화 필드를 두지 않는다.
- **원화는 소수점이 없다.** 내부 표현은 `long`(원 단위) 또는 `BigDecimal scale=0`.
  - 기존 v1 구현이 `scale=2`를 쓴 것은 원화에 맞지 않는다. 재설계에서 교정한다.
- 계산 중간값은 소수를 허용하되, **각 담보별 보상액 확정 시점에 원 미만 절사**한다.
- 절사 방향과 시점은 `03-adjudication.md`의 계산 규칙에 명시하며, 임의 변경 금지.

## 7. 개인정보 취급 등급

| 등급 | 항목 | 저장 | 로그 |
|---|---|---|---|
| 최고 | 주민등록번호 | **저장 금지** (CI/내부 고객키로 대체) | 금지 |
| 높음 | 성명, 연락처, 계좌번호, 주소 | 컬럼 암호화(AES-GCM) | 마스킹 필수 |
| 높음 | 질병분류코드, 진단명, 진료내역 | 컬럼 암호화 | **원문 로그 금지** |
| 중간 | 계약번호, 청구번호, 금액 | 평문 | 허용 |

> 민감정보 로깅은 기술 문제가 아니라 **법 위반**이다.
> 로깅 계층에서 마스킹을 "잘 하는" 것이 아니라, **민감 타입은 애초에 `toString()`이 마스킹된 값을 반환**하도록 타입 수준에서 막는다. (`07-architecture.md` 참조)
