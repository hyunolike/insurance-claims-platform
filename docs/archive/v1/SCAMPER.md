## 스캠퍼 기법
| 기법                       | 보험 도메인 적용                 | 액션 아이디어 |
| ------------------------ | ------------------------- | ---------- |
| **S (Substitute)**       | 수동 심사 → 자동 이벤트 기반 처리      | `claim.reviewed` 이벤트 수신 시 판정 로직 자동 실행 |
| **C (Combine)**          | 청구 + 알림 + 감사 로그 통합        | 이벤트 버스 → 알림 / 감사 서비스 동시에 발행 |
| **A (Adapt)**            | 토스 결제/송금 구조 → 보험금 지급      | 기존 결제 상태머신을 보험금 지급 상태로 재사용 |
| **M (Modify)**           | 동기 API → 비동기 이벤트          | REST 청구 API 이후 Kafka로 비동기 처리 |
| **P (Put to other use)** | Kafka를 로그/감사 용도로도 사용      | `claim.*` 토픽을 Data Lake/모니터링 팀에 재전송 |
| **E (Eliminate)**        | 관리자 수동 개입 최소화             | 심사 예외 기준을 Rule 엔진에 구성해 Console 의존 제거 |
| **R (Reverse)**          | “심사 후 알림” → “알림 중심 상태 추적” | 상태 변경 이벤트에 맞춰 모바일 푸시 먼저 발송, 심사 세부는 추후 보완 |
