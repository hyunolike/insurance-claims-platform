## 스캠퍼 기법
| 기법                       | 보험 도메인 적용                 |
| ------------------------ | ------------------------- |
| **S (Substitute)**       | 수동 심사 → 자동 이벤트 기반 처리      |
| **C (Combine)**          | 청구 + 알림 + 감사 로그 통합        |
| **A (Adapt)**            | 토스 결제/송금 구조 → 보험금 지급      |
| **M (Modify)**           | 동기 API → 비동기 이벤트          |
| **P (Put to other use)** | Kafka를 로그/감사 용도로도 사용      |
| **E (Eliminate)**        | 관리자 수동 개입 최소화             |
| **R (Reverse)**          | “심사 후 알림” → “알림 중심 상태 추적” |
